# 打ち手の事前知識（汎用）

アイデア在庫（`ideas/backlog.yaml`）が下限を割ったときの補充源。
「思いつかない」は在庫が空である理由にならない。ここを順に読んで補充する。

## `knowledge/landscape.yaml` との違い

| | ここ（priors） | landscape |
|---|---|---|
| 中身 | どのコンペでも同じ汎用の打ち手 | **このコンペ固有**の外部知識 |
| 出所 | この基盤に同梱 | `/survey` で調べて集める |
| 効き方 | 取りこぼしを防ぐ | 上位との差を作る |

**汎用の在庫からは汎用のアイデアしか出ない。**
ここだけで在庫を埋めると、どのコンペでも同じ実験を同じ順序で回すことになる。
landscape 由来を最低3件は在庫に入れる（`policy.landscape_min_transferred`）。

各項目は次の形で書いてある。

```
### 識別子 — 打ち手
軸 `axis` / コスト c / 期待 e

説明。

適用: いつ使うか。
```

- **コスト** は相対値。1.0 が標準的な1実験の実装＋実行コスト。
- **期待** は指標の絶対値ではなく、効いた事例での典型的な相対の大きさ。
  コンペごとに違うので、`backlog.yaml` に写すときは自分のコンペの
  ノイズ幅と CV の分散を見て数値に直す。
- ここに書いてあることは**このコンペで観測された事実ではない**。
  `ideas.evidence` に写すときは `priors/xxx.md#c01` の形で外部由来と分かるようにし、
  このコンペでの観測（`exp0003`）と混ぜない。

順序はおおむね「効く確率 × 効いたときの大きさ ÷ コスト」の降順。
上から順に消化すれば、確度の高い順に試したことになる。
