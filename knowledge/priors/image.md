# 画像・音声

### v01 — 入力解像度を上げる
軸 `preprocessing` / コスト 1.5 / 期待 細かい対象を見るタスクでは大きい

最も素直に効くことが多い一方、計算コストが二乗で増える。
効くかどうかを低コストで見るなら、少ない epoch で解像度だけ変えて比較する。

適用: p0 の走査で当たりを見る。

### v02 — augmentation の探索
軸 `preprocessing` / コスト 1.0 / 期待 データが少ないほど大きい

弱い側（flip / crop / brightness）から強い側（mixup / cutmix / RandAugment）へ。
強すぎると学習が進まないので、学習曲線を見て判断する。
**タスクの対称性を壊す augmentation を入れない**（文字認識に水平反転など）。

適用: 常に。データが少ないなら優先度を上げる。

### v03 — バックボーンを複数試す
軸 `model_family` / コスト 1.2 / 期待 大きい

CNN 系（ConvNeXt, EfficientNet）と Transformer 系（ViT, Swin）は
得意な対象が違い、予測が相関しない。両系統から1つずつ当てる。

適用: p0。

### v04 — TTA
軸 `postprocessing` / コスト 0.4 / 期待 小さいが安定して正

推論時に flip / multi-scale / crop で複数予測して平均する。
学習を回さないので安い。学習時の augmentation と整合させる。

適用: パイプラインが固まってから。

### v05 — 損失関数を不均衡に合わせる
軸 `objective` / コスト 0.6 / 期待 クラス不均衡が強いと大きい

focal loss、class weight、ArcFace 系（距離学習が効くタスク）。
指標が macro 平均なら、少数クラスの扱いが支配的になる。

適用: クラス分布が偏っているとき。

### v06 — 音声はスペクトログラムの作り方が特徴量設計そのもの
軸 `features` / コスト 0.8 / 期待 大きい

n_fft / hop_length / mel bins / 周波数レンジ を変えると別の入力になる。
画像の解像度に相当する探索軸として扱う。

適用: 音声タスクの序盤。
