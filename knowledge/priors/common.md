# 種別を問わない打ち手

## 土台（これが崩れていると以降の全数値の意味が消える）

### c01 — 評価指標の自前実装を公式定義と一致させる
軸 `metric_fidelity` / コスト 0.5 / 期待 直接の向上は無い。ずれていた場合は全実験の解釈がやり直しになる

公式定義を引き、自前実装との一致をテストで示す。ずれやすいのは平均の取り方
（サンプル平均かグループ平均か）、欠損と同値の扱い、多クラスの平均方法
（macro / micro / weighted）、上位 k の切り方。

適用: 常に、最初に。`competition.yaml` の `metric.verified` はこれが済むまで false。

### c02 — テストの作られ方に CV の切り方を合わせる
軸 `validation` / コスト 1.0 / 期待 CV-LB 相関の改善。これが低いまま進むと以降の判断が全部弱い根拠になる

train と test の関係を先に調べる。時間で分かれているのか、グループ（患者・店舗・
ユーザ）で分かれているのか、単純ランダムか。分け方が違えば CV は採点を再現しない。

適用: 常に、c01 の直後。

### c03 — リークと重複を探す
軸 `data_leak` / コスト 1.0 / 期待 当たれば桁で変わる。外れれば0

train/test 間の完全重複、ID に埋まった順序情報、時系列の未来参照、
集約特徴を作るときの自分自身の混入。ファイル名・行順・インデックスも見る。

適用: 序盤に1本当てる。見つからなくても、見つからなかったことが記録になる。

### c04 — adversarial validation で train/test の分布差を測る
軸 `validation` / コスト 0.8 / 期待 分布差がある場合、その特徴の扱いを変えるだけで効く

train と test を分類するモデルを作り、AUC を見る。0.5 付近なら同分布。
高ければ、判別に効いた特徴が分布ずれの原因。その特徴を落とす、または
test に近い train のサブセットで検証する。

適用: c02 の後。CV-LB 相関が低いときの診断としても使う。

## ほぼ確実に効く低コストの打ち手

### c05 — seed averaging
軸 `ensemble` / コスト 0.3 / 期待 分散の縮小ぶん。小さいが安定して正

同じ設定で seed を変えて複数回学習し、予測を平均する。
効き幅は小さいが、ほぼ負けない。終盤の詰めで使う。

適用: パイプラインが固まってから。序盤にやると実験の回転が落ちる。

### c06 — 後処理と閾値の最適化
軸 `postprocessing` / コスト 0.4 / 期待 F1・精度・mAP などの離散指標では大きい

指標が閾値に依存するなら、CV 上で閾値を最適化する。順位系なら順位の後処理、
確率系ならキャリブレーション（Platt / isotonic）。学習を回さずに済むので安い。

適用: 指標が離散的、または確率の絶対値を見る場合。

### c07 — 目的関数を評価指標に寄せる
軸 `objective` / コスト 0.6 / 期待 指標と損失が乖離しているほど大きい

RMSE で評価されるのに MAE で学習していないか。順位で評価されるのに
pointwise 損失を使っていないか。指標そのものが微分不可なら、その代理損失を選ぶ。

適用: 指標と既定の損失が一致していないとき。

### c08 — 全データでの再学習
軸 `model_family` / コスト 0.3 / 期待 データ量に応じる。小さいデータほど大きい

CV で確定した設定を、fold 分割せず全 train で学習し直して提出する。
検証できないので、CV が信用できるようになってから。

適用: 終盤。CV 信頼性が calibrated になってから。

## 中コストの主力

### c09 — 多様性を持たせたアンサンブル
軸 `ensemble` / コスト 1.5 / 期待 構成要素が多様なほど大きい

同じモデルの seed 違いより、違うモデル族・違う特徴集合・違う前処理の組み合わせが効く。
重みは CV 上で最適化するか、単純平均から始める。相関の低い予測を優先して混ぜる。

適用: 単体モデルの可動域を出し切ってから。

### c10 — 疑似ラベル
軸 `pseudo_labeling` / コスト 1.5 / 期待 test が大きく、予測が高精度なときに効く

test への予測を train に足して学習し直す。確信度で足切りする版と全件使う版がある。
CV の設計を間違えるとリークするので、fold ごとに疑似ラベルを作り直す。

適用: 単体モデルが十分な精度に達してから。

### c11 — 外部データ
軸 `external_data` / コスト 2.0 / 期待 当たれば大きい。規約違反のリスクあり

コンペ規約で許可されているか必ず確認する。許可されていても、
分布が違えば効かない。使う前に adversarial validation で近さを測る。

適用: 規約を確認した上で、内部データの可動域を出し切ってから。

### c12 — 過去の類似コンペの上位解法を読む
軸 `-` / コスト 0.5 / 期待 在庫補充として最も確度が高い

似た指標・似たデータ形式のコンペの1位〜5位の解法を読み、
このコンペに移せる打ち手を `backlog.yaml` に写す。
写すときは `evidence` に出典を書き、このコンペでの観測と区別する。

適用: 在庫が薄くなったとき。定期的に。
