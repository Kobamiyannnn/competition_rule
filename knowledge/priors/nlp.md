# NLP / LLM

### n01 — 事前学習モデルを複数試す
軸 `model_family` / コスト 1.0 / 期待 大きい。土台の選択が支配的

DeBERTa-v3 系は分類・回帰で強いことが多い。ドメイン特化の事前学習モデル
（科学・医療・法律）があるなら優先。サイズ違いも別モデルとして扱う。

適用: p0 の粗い走査で。

### n02 — 最大系列長を実データの分布から決める
軸 `preprocessing` / コスト 0.4 / 期待 切り詰めすぎていると大きい

トークン長の分布を見る。既定の 512 で切っていて、実際は 1500 トークンある
なら情報が落ちている。頭と尻を残す、スライディングウィンドウで分割する、
長文対応モデルに替える、の三択。

適用: 常に、序盤に。

### n03 — プーリングと head の設計
軸 `model_family` / コスト 0.6 / 期待 中程度

CLS だけでなく mean pooling / max pooling / attention pooling / 
複数層の連結を試す。学習率を層ごとに変える（layer-wise LR decay）。

適用: モデルを固めた後。

### n04 — 学習の安定化
軸 `hyperparameters` / コスト 0.8 / 期待 fold 間分散が大きいときに効く

大きなモデルは seed で結果が振れる。warmup、勾配クリッピング、
再初期化する層数（re-init last N layers）、EMA を試す。
fold 間の std が縮めば、以降の実験の判定精度が上がる。

適用: fold 間の分散がノイズ幅を超えているとき。

### n05 — LLM を使う場合はプロンプトを実験対象として記録する
軸 `objective` / コスト 0.5 / 期待 大きいが再現性が低い

プロンプト・モデル・温度・トークン数・コストを `metrics.json` の config に入れる。
プロンプトの差分は `change.diff` に書く。ここを曖昧にすると再現できない。

適用: LLM を推論に使うとき。

### n06 — 外部テキストでの継続事前学習
軸 `external_data` / コスト 2.5 / 期待 ドメインが特殊なほど大きい

コンペのデータ（test 本文を含む場合は規約を確認）で MLM を続けてから
下流タスクに fine-tune する。

適用: ドメインが一般ウェブから遠いとき。
