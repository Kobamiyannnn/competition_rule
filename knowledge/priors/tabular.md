# テーブルデータ（GBDT 中心）

### t01 — 特徴量の重要度ではなく permutation importance / null importance で選ぶ
軸 `features` / コスト 0.8 / 期待 高カーディナリティ特徴が多いほど大きい

GBDT の split gain は高カーディナリティ特徴を過大評価する。
ラベルをシャッフルして得た重要度分布と比較し、それを超えた特徴だけ残す。

適用: 特徴量が数百を超えたとき。

### t02 — ターゲットエンコーディングを fold 内で作る
軸 `features` / コスト 1.0 / 期待 カテゴリ変数が主役なら大きい

out-of-fold で作らないとリークする。CV は上がって LB は上がらない典型例。
smoothing の強さも探索対象。

適用: 高カーディナリティのカテゴリ変数があるとき。

### t03 — 集約特徴（group by 統計量）
軸 `features` / コスト 1.0 / 期待 テーブルに自然なグループがあれば大きい

ユーザ・店舗・セッションなどの単位で mean / std / min / max / count / nunique を作る。
差分（値 − グループ平均）と比（値 ÷ グループ平均）も作る。

適用: 行が独立でなく、何らかの単位に属しているとき。

### t04 — 複数の GBDT 実装を混ぜる
軸 `model_family` / コスト 1.2 / 期待 単体最良からさらに乗る

LightGBM / XGBoost / CatBoost は木の育て方とカテゴリの扱いが違うので予測が相関しない。
CatBoost はカテゴリ変数が多いデータで単体でも強いことが多い。

適用: p0 の粗い走査で3族とも当てる。

### t05 — ニューラルネットを1本混ぜる
軸 `model_family` / コスト 2.0 / 期待 GBDT との相関が低いのでアンサンブルで効く

単体では GBDT に負けることが多いが、予測の相関が低いので混ぜると効く。
数値特徴の正規化とカテゴリの埋め込みが要る。

適用: GBDT 側の可動域を出し切ってから。

### t06 — ハイパーパラメータの探索（飽和判定つき）
軸 `hyperparameters` / コスト 1.0 / 期待 既定値からなら中程度、チューニング済みからは小さい

LightGBM なら num_leaves / min_data_in_leaf / feature_fraction / bagging_fraction /
lambda_l1 / lambda_l2 / learning_rate。Optuna などで探索する。
**飽和の判定基準を先に決める**。例:「直近30試行で best がノイズ幅を超えて更新されない」。
基準を先に決めないと、ここは無限に安全な作業になる。

適用: p1。飽和したら `expctl saturate hyperparameters` で宣言し、以降触らない。

### t07 — 欠損の扱いを変える
軸 `preprocessing` / コスト 0.5 / 期待 欠損が多いと中程度

GBDT は欠損をそのまま扱えるが、欠損フラグを別特徴にする、
グループ平均で埋める、欠損数そのものを特徴にする、で挙動が変わる。

適用: 欠損率が高い列があるとき。

### t08 — 行の重み付けと外れ値の扱い
軸 `preprocessing` / コスト 0.6 / 期待 分布が歪んでいると中程度

test に近い行を重く学習する。目的変数を log / rank / quantile 変換する
（指標が RMSE 系で分布が歪んでいるとき）。

適用: 目的変数が裾の重い分布のとき。
