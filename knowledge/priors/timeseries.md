# 時系列・予測

### s01 — 検証を時間で切る
軸 `validation` / コスト 0.8 / 期待 これを外すと以降の判断が全部無効になる

ランダム分割は未来を見る。時系列分割（expanding / sliding window）にする。
test と同じ予測期間の長さで検証する。

適用: 常に、最初に。

### s02 — ラグ特徴とローリング統計
軸 `features` / コスト 1.0 / 期待 大きい

ラグは予測時点で入手可能な範囲だけ使う。ローリング平均・標準偏差・
トレンド・差分。**シフト量を間違えると未来参照になる**ので、
作った特徴が予測時点で本当に入手できるかを1つずつ確認する。

適用: 常に。

### s03 — 目的変数の変換
軸 `preprocessing` / コスト 0.5 / 期待 スケールが系列ごとに違うと大きい

log1p、系列ごとの正規化、差分化。指標が相対誤差系なら log 変換が素直。

適用: 系列間でスケールが桁違いのとき。

### s04 — 階層構造と系列ごとのモデル分割
軸 `model_family` / コスト 1.5 / 期待 系列の性質が分かれているときに大きい

全系列を1モデルで扱うか、クラスタごとに分けるか。
需要が薄い系列と厚い系列は挙動が違うので、分けると効くことがある。

適用: 系列数が多く、性質が分かれているとき。

### s05 — 直近データの重み付け
軸 `preprocessing` / コスト 0.5 / 期待 非定常性が強いと大きい

古いデータを軽く、直近を重く学習する。学習期間そのものを短く切るのも同じ発想。
どこまで遡るかを探索対象にする。

適用: 分布が時間で動いているとき（adversarial validation で確認できる）。

### s06 — 統計モデルを1本混ぜる
軸 `ensemble` / コスト 1.0 / 期待 GBDT との相関が低い

季節性が強いなら統計的手法（指数平滑、季節分解）が単体でも健闘し、
機械学習モデルとの相関が低いのでアンサンブルで効く。

適用: 明確な季節性があるとき。
